⚙️
ระบบอัตโนมัติ (Cron Jobs / Socket.io)
ประมวลผลเบื้องหลัง — ตรวจสอบ Overdue, Expired, แจ้งเตือนอัตโนมัติ
🕛 00:00 ทุกวัน (เที่ยงคืน)
รีเซ็ตระบบประจำวัน
  • ยกเลิก pending ทั้งหมดที่ค้างสิ้นวัน
  • ยกเลิกคิว waiting/called ทั้งหมด
  • ตรวจสอบรายการ overdue → อัพเดตสถานะ + ส่ง Email
🕗 08:00 ทุกวัน (เช้า)
แจ้งเตือนใกล้ครบกำหนด
  • ตรวจรายการที่เหลือ 1-3 วันจะครบกำหนด
  • ส่ง Email + In-App แจ้งเตือนนักศึกษา
🕐 16:00 ทุกวัน (บ่าย)
แจ้งเตือนด่วน
  • ตรวจรายการที่ครบกำหนดคืนวันนี้
  • ส่ง Email + In-App "ครบกำหนดคืนวันนี้!"
⏱️ ทุก 1 นาที
ตรวจสอบ Expired
  • ตรวจคิว called ที่เกิน 5 นาที → expired → เรียกคิวถัดไป
  • ตรวจ pending ที่เกิน 15 นาที → rejected อัตโนมัติ
🎓 บทบาท: นักศึกษา (Student)
ใช้งานผ่าน Mobile App — มี JWT Authentication — เข้าถึง API ผ่าน /api/*
🔐 1. เข้าสู่ระบบ (Login)
Endpoint: POST /api/login.php
Input: รหัสนักศึกษา (studentId) + เลขบัตรประชาชน (citizenId)
Output: JWT Token (อายุ 8 ชั่วโมง, role: student)
Rate Limit: สูงสุด 15 ครั้ง / 15 นาที
🔍 2. ดูรายการอุปกรณ์
Endpoint: GET /api/get_equipments.php (ไม่ต้อง Login)
ข้อมูลที่เห็น: ชื่ออุปกรณ์, จำนวนที่เหลือ (available_quantity), จำนวนคิว (queue_count)
รายละเอียด: GET /api/get_detail.php?id=X
📦 3. ยืมอุปกรณ์ (Checkout)
Endpoint: POST /api/checkout.php (ต้อง Login)
เงื่อนไข:
  • ยืมอุปกรณ์เดิมซ้ำไม่ได้ (1 คน : 1 ชิ้น/รุ่น)
  • ห้ามอยู่ในคิวของอุปกรณ์นั้น
  • ยืมสูงสุด 5 ชิ้น/วัน
  • ต้องมี stock เหลือ (ถ้าหมดให้จองคิว)
  • ห้ามยืมถ้ามีคิวที่ถูกเรียกอยู่ (คนอื่น)
ผลลัพธ์: สร้าง record สถานะ pending หมดอายุใน 15 นาที
🔢 4. จองคิว (Join Queue)
Endpoint: POST /api/join_queue.php (ต้อง Login)
เงื่อนไข: ห้ามยืมชิ้นนั้นอยู่, ห้ามอยู่ในคิวซ้ำ, คิวเต็ม 10 คน
ผลลัพธ์: สถานะ waiting ตำแหน่งลำดับที่ N
❌ 5. ยกเลิกคำขอยืม
Endpoint: POST /api/cancel_request.php
ผลลัพธ์: สถานะเปลี่ยนเป็น rejected ถ้าสถานะเดิมเป็น borrowed จะคืน item กลับ stock
❌ 6. ยกเลิกคิว
Endpoint: POST /api/cancel_queue.php
ผลลัพธ์: สถานะเปลี่ยนเป็น cancelled + เรียงลำดับคิวใหม่
⚠️ 7. แจ้งอุปกรณ์สูญหาย/ชำรุด
Endpoint: POST /api/report_lost.php
เงื่อนไข: สถานะต้องเป็น borrowed หรือ overdue เท่านั้น
Input: วันที่สูญหาย + หมายเหตุ
ผลลัพธ์: สถานะเปลี่ยนเป็น damaged_lost
📄 8-10. ดูประวัติ / แจ้งเตือน / แก้ไขโปรไฟล์
  • GET /api/get_borrowed.php — ดูประวัติการยืมทั้งหมด
  • GET /api/my_queue.php — ดูคิวของตัวเอง
  • GET /api/get_notifications.php — ดูการแจ้งเตือน (alert / announcement)
  • POST /api/update_student_profile.php — แก้ไขชื่อ, อีเมล, เบอร์โทร, รหัสผ่าน
🛡️ บทบาท: บรรณารักษ์ (Admin)
ใช้งานผ่าน Admin Web — ต้อง Login ด้วย JWT (role: admin) — เข้าถึง API ผ่าน /api/admin/*
📊 1. ดู Dashboard
Endpoint: GET /api/admin/dashboard
ข้อมูล KPI: ยืมวันนี้, คืนแล้ว, เลยกำหนด, รออนุมัติ
Chart Data: กราฟสถิติตามวันที่เลือก
Recent Activity: 20 รายการล่าสุด
✅ 2-3. ดูคำขอ + อนุมัติ/ปฏิเสธ
ดูคำขอ: GET /api/admin/requests?status=pending&page=1&limit=50
ดำเนินการ: POST /api/admin/update-request
Actions ที่ทำได้:
  • approve — อนุมัติ (ล็อค item + เปลี่ยนสถานะ borrowed)
  • reject — ปฏิเสธ (คืน item ถ้ามี)
  • return — รับคืน (คืน item + เรียกคิวถัดไป)
  • lost — สูญหาย (item → damaged_lost)
📱 4-5. สแกน QR/Barcode จ่าย + รับคืน
จ่ายอุปกรณ์: POST /api/admin/pickup_queue.php
  • รับ queue_id (LBxxx = borrow request / ตัวเลข = queue item)
  • รับ barcode (รหัสครุภัณฑ์ หรือ 'AUTO' เพื่อเลือกอัตโนมัติ)
  • รองรับจ่ายทีเดียวหลายชิ้น (Group Pickup)

รับคืนอุปกรณ์: POST /api/admin/return_by_barcode.php
  • รับ barcode → ค้นหา item → ค้นหา borrowed record → คืน
  • Socket emit scan_success สำหรับ Realtime UI
📦 6. จัดการอุปกรณ์ (CRUD)
  • GET /api/admin/equipments — ดูรายการทั้งหมด
  • POST /api/admin/equipments — เพิ่มอุปกรณ์ใหม่ (auto-category, สร้าง items อัตโนมัติ)
  • PUT /api/admin/equipments/:id — แก้ไข (ปรับ stock/items อัตโนมัติ)
  • DELETE /api/admin/equipments/:id — ลบ (ถ้าไม่มีประวัติยืม)
  • GET /api/admin/equipments/:id/items — ดูชิ้นย่อยแต่ละ item
🔢 7. จัดการคิว
  • GET /api/admin/queue/:equipmentId — ดูคิวของอุปกรณ์
  • POST /api/admin/queue/:id/skip — ข้ามคิว (expired → เรียงใหม่ → เรียกคิวถัดไป)
📢 8. ส่งประกาศ / แจ้งเตือน
Endpoint: POST /api/admin/notifications
Target: 'all' (ทุกคน) หรือ email เฉพาะคน
รองรับ: แนบรูปภาพ (Multer upload, 5MB max)
การทำงาน: บันทึก DB ทันที → ส่ง Email ในพื้นหลัง (non-blocking)
📈 9-10. รายงาน + ข้อมูลผู้ใช้
  • GET /api/admin/reports?type=monthly — สถิติรายเดือน
  • GET /api/admin/reports?type=yearly — สถิติรายปี
  • GET /api/admin/reports?type=equipment_stats — อุปกรณ์ยอดนิยม
  • GET /api/admin/reports/equipment-breakdown — สถิติแยกตามอุปกรณ์
  • GET /api/admin/reports/student-breakdown — สถิติแยกตามนักศึกษา
  • GET /api/admin/users — ดูผู้ใช้ที่มีประวัติยืม
  • GET /api/admin/user-history/:studentId — ดูประวัติรายบุคคล

📡 Socket.io — Realtime Updates
ทุก Action ที่มีการเปลี่ยนแปลงข้อมูล จะ emit event:
  • io.emit('data_updated') — แจ้ง Client ทุกตัวให้ refresh ข้อมูล
  • io.emit('scan_success', { type, message, barcode }) — แจ้งผลสแกน QR/Barcode
📋 Use Case Diagram — Flow การยืมอุปกรณ์ (Equipment Borrowing System)
แผนภาพ Use Case มาตรฐาน UML สำหรับขั้นตอนการยืมอุปกรณ์ แสดง Actor, ความสัมพันธ์ <<include>> และ <<extend>>
─── Association (เส้นเชื่อมต่อ Actor) - - -► <<include>> (ต้องทำเสมอใน Flow ยืม) - - -► <<extend>> (ส่วนขยายตามเงื่อนไขหรือการตัดสินใจ) 🔲 System Boundary (ขอบเขตระบบยืมอุปกรณ์)
📖 ตารางรายละเอียด Use Case: การยืมอุปกรณ์
Use Case ประเภท Actor ที่เกี่ยวข้อง คำอธิบาย / เงื่อนไข (Conditions & Flow)
ขอยืมอุปกรณ์ (Checkout) Base Use Case นักศึกษา (Primary) นักศึกษาเลือกอุปกรณ์ที่ต้องการยืมและกดยืนยันคำขอยืมผ่าน Mobile App
ตรวจสอบสิทธิ์และโควตา <<include>> ระบบ (อัตโนมัติ) ระบบตรวจ 1 คน ยืม/จองอุปกรณ์ซ้ำรุ่นเดิมไม่ได้, ไม่เกิน 5 ชิ้น/วัน, และไม่อยู่ในคิวของอุปกรณ์นั้น
ตรวจสอบและล็อคสต๊อก <<include>> ระบบ (ฐานข้อมูล) ใช้ SELECT ... FOR UPDATE ล็อค equipment_items ชิ้นที่ว่าง ป้องกัน race condition
สร้างคำขอ Pending 15 นาที <<include>> ระบบ (ฐานข้อมูล) บันทึกลงตาราง borrowed กำหนด reservation_expires_at = NOW() + 15 MINUTE
ส่งการแจ้งเตือนคำขอ <<include>> ระบบ (Email + In-App) ส่งอีเมลยืนยันการรับคำขอ พร้อมบันทึก In-App Notification เพื่อให้นักศึกษานำ QR ไปรับที่ห้องสมุด
สแกน QR & จ่ายอุปกรณ์จริง <<extend>> นักศึกษา + บรรณารักษ์ นักศึกษาแสดง QR Code เจ้าหน้าที่สแกน Barcode อุปกรณ์ตัวจริง ระบบเปลี่ยนสถานะเป็น borrowed และส่งอีเมลยืนยัน
ยกเลิกคำขอยืมโดยนักศึกษา <<extend>> นักศึกษา นักศึกษากดยกเลิกคำขอยืมด้วยตนเองก่อนหมดเวลา ระบบปลดล็อค item กลับสต๊อกและเปลี่ยนสถานะเป็น rejected
ตัดคำขอหมดเวลา (15 นาที) <<extend>> ระบบอัตโนมัติ (Cron) Cron Job ตรวจสอบทุก 1 นาที หากเกิน 15 นาทีแล้วไม่มารับ ระบบจะเปลี่ยนเป็น rejected อัตโนมัติ
ปฏิเสธคำขอยืม <<extend>> บรรณารักษ์ (Admin) เจ้าหน้าที่กดปฏิเสธคำขอจากหน้า Requests ระบบคืน item กลับคลังและแจ้งเตือนนักศึกษา

จองคิวอุปกรณ์ (Join Queue) Base Use Case นักศึกษา (Primary) เมื่ออุปกรณ์ในคลังหมด (available_quantity = 0) นักศึกษาสามารถกดยืนยันเพื่อขอรับคิวรออุปกรณ์ชิ้นนั้น
ตรวจสอบเงื่อนไขการเข้าคิว <<include>> ระบบ (อัตโนมัติ) ตรวจว่าไม่ได้กำลังยืมอุปกรณ์นี้อยู่, ไม่อยู่ในคิวเดิมซ้ำ, และคิวรวมไม่เกิน 10 คน
บันทึกลำดับคิว (Position) <<include>> ระบบ (ฐานข้อมูล) บันทึกลง equipment_queue สถานะ waiting โดยให้ลำดับ position = max(position) + 1
ส่งแจ้งเตือนยืนยันการจองคิว <<include>> ระบบ (Email + In-App) ส่งอีเมลยืนยัน "คุณอยู่ในคิวลำดับที่ N เมื่อถึงคิวจะมีเวลา 5 นาทีในการมารับอุปกรณ์"
ยกเลิกคิวตนเอง <<extend>> นักศึกษา นักศึกษากดยกเลิกคิวจากหน้า My Queue ระบบเปลี่ยนเป็น cancelled และคำนวณเรียงลำดับคิวที่เหลือใหม่
เรียกคิวเมื่ออุปกรณ์ว่าง (Call Next) Triggered UC ระบบอัตโนมัติ / บรรณารักษ์ เมื่อมีผู้คืนอุปกรณ์ หรือคิวก่อนหน้าถูกข้าม ระบบจะดึงคิวแรกสถานะ waiting เปลี่ยนเป็น called พร้อมตั้งเวลานับถอยหลัง 5 นาที
รับอุปกรณ์ตามคิว <<extend>> นักศึกษา + บรรณารักษ์ นักศึกษามารายงานตัวภายใน 5 นาที เจ้าหน้าที่สแกน Barcode จ่ายอุปกรณ์ ระบบเปลี่ยนคิวเป็น completed และสร้างประวัติการยืม
ข้ามคิวเมื่อเกิน 5 นาที (Expired) <<extend>> ระบบอัตโนมัติ (Cron) Cron Job ตรวจสอบทุก 1 นาที หาก NOW() > expires_at จะเปลี่ยนเป็น expired แจ้งเตือนคิวถูกข้าม และเรียกคิวถัดไปทันที
ข้ามคิวโดยเจ้าหน้าที่ (Manual Skip) <<extend>> บรรณารักษ์ (Admin) เจ้าหน้าที่กดปุ่ม Skip คิวจากหน้า Queue Management ระบบตัดคิวเป็น expired แจ้งเตือนผู้ใช้ และเรียกคิวถัดไป

ภาพที่ 1: ผังงานการทำงานของระบบยืม-คืนอุปกรณ์ (ผู้ใช้งานระบบ และผู้ดูแลระบบ)
📦 ผังงานระบบสำหรับโปรเจกต์ Project Libraries (ประยุกต์ Flow ยืม และ Flow จองคิว)
ผังงานนำโครงสร้างมาตรฐานข้างต้นมาจับคู่กับระบบจริงในโปรเจกต์ห้องสมุด: Flow การยืมอุปกรณ์ (มีสต๊อก) และ Flow การจองคิว (ของหมดสต๊อก รอคิว 5 นาที)
📦 Flow การยืมอุปกรณ์ (Borrow Flow)
  1. เข้าสู่ระบบ (นศ.) → รหัสนักศึกษา + บัตร ปชช.
  2. ตรวจเช็คสถานะพัสดุ → มีอุปกรณ์ว่าง (Stock > 0)
  3. กรอกข้อมูลการยืม → ตรวจโควตา (ไม่เกิน 5 ชิ้น/วัน, 1 ชิ้น/รุ่น)
  4. ส่งคำขอยืม → สร้างสถานะ pending (หมดอายุใน 15 นาที)
  5. รออนุมัติยืม:
    • ถ้าผ่าน: นศ. แสดง QR → เจ้าหน้าที่สแกน Barcode จ่าย → รับพัสดุ (Borrowed)
    • ถ้าไม่ผ่าน / เกิน 15 นาที: ยกเลิกคำขอ คืนสต๊อก
  6. ออกจากระบบ
🔢 Flow การจองคิวอุปกรณ์ (Queue Flow)
  1. เข้าสู่ระบบ (นศ.) → รหัสนักศึกษา + บัตร ปชช.
  2. ตรวจเช็คสถานะพัสดุ → อุปกรณ์หมด (Stock = 0)
  3. กรอกข้อมูลการจองคิว → ตรวจคิวไม่เกิน 10 คน และไม่จองซ้ำ
  4. ส่งคำขอจองคิว → ได้รับลำดับคิว สถานะ waiting
  5. รอการเรียกคิว:
    • เมื่อมีคนคืนพัสดุ → ระบบเปลี่ยนเป็น called (มีเวลา 5 นาที)
    • มารับทัน: สแกน Barcode จ่าย → รับพัสดุ (คิว Completed)
    • ไม่มารับเกิน 5 นาที: ข้ามคิวอัตโนมัติ (Expired) → เรียกคนถัดไป
  6. ออกจากระบบ

🛡️ Admin เลือก Action
POST /api/admin/update-request — ส่ง { id, action, fine }
Actions: approve | reject | return | lost
↓
✅ action = "approve" (อนุมัติ)
  1. ค้นหา equipment_item ที่ว่าง → SELECT ... FOR UPDATE (ล็อค row)
  2. ถ้าไม่มี item ว่าง → ❌ "อุปกรณ์หมด ไม่สามารถอนุมัติได้"
  3. อัพเดต item สถานะ → borrowed
  4. อัพเดต borrowed สถานะ → borrowed
  5. 📧 Email: "✅ ยืนยันยืมอุปกรณ์สำเร็จ กรุณาไปรับที่ห้องสมุด"
❌ action = "reject" (ปฏิเสธ)
  1. ถ้าสถานะเดิมเป็น borrowed → คืน item กลับ stock (available)
  2. อัพเดต borrowed สถานะ → rejected
  3. 📧 Email + 🔔 In-App: "คำขอยืมถูกยกเลิกโดยผู้ดูแลระบบ"
🔄 action = "return" (รับคืน)
  1. ค้นหา item ที่สถานะ = borrowed → เปลี่ยนเป็น available
  2. อัพเดต borrowed สถานะ → returned + return_date = NOW()
  3. 📧 Email: "✅ คืนอุปกรณ์สำเร็จ ขอบคุณที่ใช้บริการ"
  4. ⚡ เรียกคิวถัดไปอัตโนมัติ (callNextInQueue) → ถ้ามีคนรอ
⚠️ action = "lost" (สูญหาย/ชำรุด)
  1. ค้นหา item ที่สถานะ = borrowed → เปลี่ยนเป็น damaged_lost
  2. อัพเดต borrowed สถานะ → damaged_lost + return_date = NOW()
  3. 🔔 In-App: "อุปกรณ์ถูกบันทึกว่าสูญหาย/ชำรุด กรุณาติดต่อบรรณารักษ์"
↓

📢 Admin ส่งประกาศเอง
POST /api/admin/notifications
  • target: 'all' (ส่งทุกคนที่มี email) หรือ email เฉพาะคน
  • แนบรูป: รองรับ Multer upload (max 5MB)
  • การทำงาน: บันทึก DB ทันที (type: announcement) → ส่ง Email ในพื้นหลัง (ไม่ block UI)
📊 Status Lifecycle — การเปลี่ยนสถานะในระบบ
แสดงทุกสถานะและเส้นทางการเปลี่ยนแปลงของแต่ละ Table
📦 borrowed table — วงจรสถานะการยืม
ทุกรายการเริ่มที่ pending และจบที่สถานะใดสถานะหนึ่ง
pending → borrowed → returned (Flow ปกติ: ยืม → อนุมัติ → คืน)
pending → rejected (Admin ปฏิเสธ / เกิน 15 นาทีไม่มารับ)
pending → cancelled (นศ. ยกเลิกเอง / Cron สิ้นวัน)
borrowed → overdue → returned (เลยกำหนด → คืนช้า)
borrowed → damaged_lost (สูญหาย/ชำรุด — นศ. แจ้งเอง หรือ Admin บันทึก)
overdue → damaged_lost (เลยกำหนด + สูญหาย)
🔢 equipment_queue table — วงจรสถานะคิว
ทุกคิวเริ่มที่ waiting
waiting → called → completed (Flow ปกติ: รอ → ถูกเรียก → มารับทัน)
called → expired (ไม่มาภายใน 5 นาที / Admin ข้ามคิว)
waiting → cancelled (นศ. ยกเลิกคิวเอง)
waiting / called → expired (Cron 00:00 รีเซ็ตสิ้นวัน)
🔧 equipment_items table — สถานะอุปกรณ์ตัวจริง
แต่ละรายการอุปกรณ์ (equipment) มีหลาย items (ชิ้นย่อยตัวจริง)
available ⇄ borrowed (ยืม ↔ คืน — สลับไปมาได้)
borrowed → damaged_lost (สูญหาย/ชำรุด — ต้อง Admin แก้ไขกลับเอง)
available → damaged_lost (Admin ปรับ available_quantity ลง)

👥 ตารางเกี่ยวกับผู้ใช้ (Users & Staff)
  • users: จัดเก็บข้อมูลบัญชีผู้ใช้, รหัสผ่าน, และสิทธิ์ (student, admin)
  • student_profiles: ข้อมูลประวัตินักศึกษา (student_id เป็น PK อ้างอิง user_id)
  • employees: ข้อมูลเจ้าหน้าที่/บรรณารักษ์ (emp_id, citizen_id สำหรับ login admin)
📦 ตารางเกี่ยวกับอุปกรณ์ (Inventory)
  • equipments: ข้อมูลรุ่นอุปกรณ์หลัก (ชื่อ, หมวดหมู่, ราคา, วันยืมสูงสุด, จำนวนรวม)
  • equipment_items: ชิ้นอุปกรณ์ตัวจริงแต่ละตัว (full_asset_code, barcode, สถานะ available/borrowed/damaged_lost)
🔄 ตารางการทำรายการ (Transactions)
  • borrowed: ประวัติการยืม-คืน (student_id, equipment_id, วันที่ยืม-คืน, สถานะ pending/borrowed/returned/overdue)
  • equipment_queue: รายการจองคิวเมื่อของหมด (ลำดับ position, สถานะ waiting/called/completed/expired)
🔔 ตารางการแจ้งเตือน (Notifications)
  • notifications: บันทึกข้อความแจ้งเตือน (target email หรือ 'all', หัวข้อ, เนื้อหา, type: alert/announcement)
